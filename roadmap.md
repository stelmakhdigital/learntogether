# Roadmap — learntogether

Порядок этапов фиксированный: следующий этап не начинается, пока не принята приёмка
предыдущего. Приёмка — проверяемое утверждение, а не ощущение готовности.
Отметка: `[x]` только вместе с коммитом этапа.

## Открытые проверки (до конца этапа 0)

- [x] `better-sqlite3`: FTS5 есть в готовой сборке, `db.loadExtension()` работает, prebuilds внутри tarball — установка без node-gyp. Ограничение: glibc >= 2.34
- [x] Кандидаты OS keyring: `@napi-rs/keyring` 2.x активен, Credential Manager и Keychain без системных зависимостей, Linux по D-Bus; keytar и npm `secret-service` мертвы
- [x] Токенизатор: `tokenizers-wasm` считает Qwen2/Qwen3 и Llama 3.x точно, 7-14M ток/с; погрешность `chars/4` измерена (русский занижает в 1.3 раза, LaTeX в 1.7)
- [ ] Живые сверки на целевых серверах: `prompt_eval_count` (Ollama) и наличие `/v1/embeddings` — Ollama на этой машине не установлена. llama.cpp сверен (`docs/probes/2026-11-25-llama-cpp.md`, `/apply-template` + `/tokenize` против `usage`, расхождение 0); vLLM сверен 2026-11-29 (`docs/probes/2026-11-29-vllm.md`): `/apply-template` нет, точный размер хода берётся из `usage.prompt_tokens` того же запроса (D-072)
- [ ] `tokenizers-wasm` в версии release candidate: следим за API, план на случай переезда на стабильную версию
- [x] Эталон FSRS: официального файла test-vectors у организации нет; фактические эталоны — зашитые векторы рейтингов и интервалов в py-fsrs и ts-fsrs, дефолтные веса сверяются поэлементно
- [x] Различия wire-формата tool calling у Ollama / llama.cpp / vLLM / LM Studio / OpenAI / Anthropic — сводка в `docs/tool-contracts.md` и в решениях D-024…D-029
- [x] Настройки electron-builder: Linux и Windows собираются с Linux-раннера (Windows через wine), macOS — только на macOS-раннере; unsigned проходит; AppImage обязателен toolset 1.0.3 из-за FUSE2 на Ubuntu 24.04+
- [x] Обновление без подписи: работает на Windows (nsis) и Linux (AppImage, deb), на macOS не работает вовсе
- [ ] Матрица отвергаемых ключей JSON Schema у Anthropic и точный текст ошибок OpenAI strict — docs.claude.com не резолвится, platform.openai.com отдаёт 403; проверять на живом ключе на этапе 2
- [x] Загрузка `better-sqlite3` внутри Electron — проверено живьём: Electron 45.5.0 с `ELECTRON_RUN_AS_NODE=1`, SQLite 3.54.1, FTS5 и поиск по-русски работают, `THREADSAFE=2`. CI-проверка появится вместе с Electron-зависимостью на этапе 8
- [ ] Реальное wall-time unit и e2e на этом монорепо — цифры до появления кода остаются оценками
- [x] Наличие `/embeddings` у целевых серверов: OpenAI-совместимый `/v1/embeddings` есть у Ollama, vLLM, LM Studio и llama.cpp; у llama.cpp `--embedding` отключает чат в том же инстансе — отсюда отдельный процесс под эмбеддинги
- [ ] Бенч эмбеддингов на этом железе: скорость `llama-server --embedding --pooling cls` на батчах по 8 и 64, время brute-force поиска по 50k векторов в SQLite — этап 4
- [ ] Собственный корпус из 200 утверждений (ru + en) для проверки выбора модели эмбеддингов и значения k в RRF — этап 4
- [ ] Время brute-force поиска по 50k векторов в SQLite на целевом железе
- [x] Стоимость и время CI: для публичного репо стандартные раннеры бесплатны и не тратят включённый compute (проверено по докам биллинга), параллельность Free-плана 20 задач, из них 5 macOS; узкое место — не минуты, а параллельность

## Этап 0 — Дисквери и проектирование

Цель: снять все технические допущения, зафиксировать архитектуру и контракты.

- [x] Скауты закрыли список проверок выше; оставшиеся привязаны к этапам, где выполняются
- [x] Архитектурный документ: границы пакетов, схема БД, контракты моделей, жизненный цикл хода — `docs/architecture.md`
- [x] Контракт инструментов ученику и остальных: JSON Schema, наборы, репарация — `docs/tool-contracts.md`
- [x] Директива методики в одном файле — `docs/teaching-method.md`
- [x] Все решения с причинами в `PROJECT_MEMORY.md` (D-001…D-040)

Приёмка: от этапа 1 не осталось решений, зависящих от непроверенного. Живые сверки
с серверами моделей — этап 2, загрузка native-модуля в собранном приложении и
реальное wall-time — этап 1, эмбеддинги и brute-force — этап 4.

- [ ] Импорт конфига локального сервера моделей — перенесено на этап 2: делать его до живых
  серверов нечего, формат разбора оказался бы догадкой
- [x] Логирование, кольцевой буфер диагностики — `packages/server/src/diagnostics.ts`:
  кольцо на 500 записей, постоянная таблица `event`, обрезка длинных сообщений, `prune`.
  В процесс сервера не подключён: `log` в `main.ts` пишет в stdout; подключение и маршрут

- [x] CI: lint, слои, typecheck, unit и contract на фикстурном транспорте, сборка — прогон зелёный
- [x] Экспорт читаемых файлов из БД (атомарная запись, детерминированный порядок) — сессии,

Приёмка: на чистом клоне `pnpm install && pnpm test && pnpm build` зелёные; сервер стартует против фикстурной модели; экспорт побайтово идентичен при повторе.

Частично: сервер поднят живьём 2026-11-28 против llama.cpp — приёмка «сервер стартует
против модели» закрыта на живом транспорте, маршрут диагностики и подключение кольца —
этап 7.

## Этап 2 — Слой моделей и контекст

- [ ] Адаптеры: OpenAI-совместимый chat/completions — есть, replay на живых трассах проходит;
  Anthropic messages и Ollama — нет; профиль эндпоинта пока один
- [x] Пробирование возможностей + хранение пробы + явный вопрос при неизвестном —
  `packages/models/src/probe.ts` (семейство OpenAI-совместимых, llama.cpp проверен живьём),
  строка в `model_info`, отказ по неизмеренному контексту в `budgetFor` (D-055)
- [x] Нормализация и репарация tool calling; отказ вместо тихого фолбэка — накопление по индексу,
  обратимые приведения с записью в `repair`, уровни 2 и 3 как отказ; проверено на фикстурных
  трассах, живые трассы появятся вместе с адаптерами
- [ ] Бюджеты по ролям, компакция: компакция есть — одно активное сводка + watermark
  (`packages/server/src/context.ts`, таблица `compaction`), размер хода меряется точным
  счётчиком сервера (D-051), инвариант «вход не растёт с длиной урока» покрыт тестом.
  Раскладки по ролям (`role_assignment`) нет: один профиль — один бюджет
- [ ] Точный счёт токенов как условие урока: сервер без `/apply-template`+`/tokenize`
  не получает хода (D-051); `tokenizers-wasm` по файлу токенизатора — задел для
  серверов, которые не отдают счёт
- [ ] N профилей эндпоинтов, ключ в keyring, ротация без перезапуска

Приёмка: replay-набор wire-трасс проходит; инвариант компакции (суммарные токены входа не растут на длинной сессии) покрыт тестом; смена контекстного окна сервера подхватывается без ручного пина.

Частично: пробирование и OpenAI-совместимый адаптер закрыты; компакции, ролевых бюджетов и
второго профиля нет. Живой запуск 2026-11-28 показал главный незакрытый пункт: в запрос хода
собирается только последнее сообщение ученика, истории разговора нет — на втором ходе модель
не вызвала ни одного инструмента и начала урок заново.

## Этап 3 — Ядро методики

- [ ] Замер понимания: протокол зондирования, граница «держу / не держу», уверенность —
  `probe_record` пишет в `probe_item` (переходы domain), сводка состояния показывает
  держимое, границу и отсутствие; открытого вопроса отдельным инструментом (`ask_learner`)
  нет — учитель спрашивает текстом, ответ ученика приходит следующим ходом
- [ ] Постановка цели: `goal_state` + `goal` в базе (пункты и критерий готовности), сессия
  переходит в `planning`; разбор одного расплывчатого запроса в несколько целей нет
- [x] План: дерево зависимостей, обоснование каждого узла, прунинг держимого — `plan_set` и
  `packages/data/src/repos/plan.ts`; узел без «зачем» и план из держимого отклоняются,
  держимый остаётся в плане как `pruned_held`. Нижнего разрешения для показа и пометки
  `done` по узлам нет: опора шага на узел появится вместе с графом (этап 4)
- [x] Цикл обучения: один шаг рассуждения, проверка после каждого шага, ремонт до опоры — на
  фикстурном транспорте и живьём (2026-11-28, Qwen2.5-7B: `record_step` → `present_step`,
  шаг и лента ординалов легли в базу)
- [x] Вызовы инструментов как единственный путь вопроса; состояния проверки; повторный вызов при битых
  аргументах — откат с текстом проверки, лимит отказов на инструмент
- [x] Хранение хода, покрытия, ответов, мыслей; отмена, пауза, продолжение — ход, отмена
  и ответы есть (сверка свободного ответа — вызов `grade_answer`, D-059): `/sessions/:id/turn`, `/turn/cancel`, `/sessions/:id/check` и
  `/check/answer` (выбор учится механически по эталону, свободный ответ сверяет модель,
  вердикт пишется ровно один раз — D-056). Паузы нет отдельной сущности: между ходами
  состояния не теряются, «продолжить» — следующее сообщение ученика (D-062). Покрытием
  служат узлы плана и шаги; отдельная таблица появится с графом (этап 4)

Приёмка: на фикстурной модели полный проход сессии без ручных правок; нет ни одной проверки без шага и ни одного шага без проверки; ремонт локален (не переписывает пройденное).

Закрыта 2026-11-28: `packages/server/test/lessonFlow.test.ts` проходит урок через
HTTP-маршруты на скриптованной модели (замер → цель → план с pruнингм → шаг →
проверка → ответ → принятый шаг → следующий шаг) и проверяет инварианты после прохода;
тот же прогон повторён живой Qwen2.5-7B вплоть до ремонта шага.

## Этап 4 — Граф знаний и поиск

- [x] Узлы, цепочки, провенанс; дедупликация формулировок; удаление без висячих ссылок
- [ ] Полнотекстовый поиск + семантический; гибридная выдача (лексика есть, семантика ждёт эмбеддинговую модель: `/v1/embeddings` на живом сервере не пробован)
- [ ] UI графа: поиск по формулировкам, чтение узла с цепочками, сомнениями и переходом
  к уроку — есть (`apps/ui/src/Library.tsx`, экран «Библиотека», `pnpm screens`);
  инкрементальная укладка, виртуализация и переход к источнику — нет
- [ ] Импорт заметок и извлечение из сессий с покрытием и ретраем

Приёмка: 20k узлов остаются интерактивными; отклик поиска < 150 мс; удаление узла не оставляет битых ссылок (тест); извлечение идемпотентно при повторном прогоне.

## Этап 5 — Практика и отложенные повторения

- [x] Планировщик повторений в ядре, эталонные регрессионные тесты (FSRS-6, эталон ts-fsrs 6.0.1 в devDependency)
- [x] Генерация задач из графа: вариативность, отсутствие подсказки термином, адаптация по ответам (условие без названия темы и повтор формулировки отсекаются механически; адаптация идёт оценкой планировщику)
- [x] Очередь: давность, сомнения, результат; защита от дублей и от «пустого дня» (узлы одной цепочки в одно окно не попадают, если не созрело ничего — ближайший элемент с `early`)
- [ ] Покрытие источников в очереди практики — перенесено в этап 6, вместе с самими источниками
- [x] Разделение: узнавание vs припоминание vs перенос (формы recall/reasoning/transfer живут раздельно, узнавание отсекается запретом термина в условии)
- [x] Экран очереди практики: что созрело и почему (сомнение, срок, «ещё не повторялось»),
  кнопка «Начать практику» ведёт в сессию вида practice; самооценки на экране нет —
  рейтинг это наш вердикт решённой задаче (apps/ui/src/Review.tsx)

Приёмка: инварианты планировщика на эталонной последовательности; очередь не теряет материалы и не дублирует карточку в одном окне; практика ссылается на узлы графа.

## Этап 8 — Расширяемость
