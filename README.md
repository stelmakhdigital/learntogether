# learntogether

Локальный тренажёр понимания. Система сначала выясняет, что ты действительно
держишь в голове, затем строит минимальный путь к цели и ведёт по нему одним шагом
рассуждения за раз, проверяя каждый шаг. Результат оседает в графе знаний, из
которого потом растут практика и отложенные повторения.

Работает с локальной моделью. Внешние провайдеры — опция, а не зависимость: ни одна
функция не должна отказывать из-за отсутствия сети или подписки.

## Состояние

Работает урок одним ходом: сервер поднимается против локального `llama-server`, пробует
эндпоинт (контекст, вызовы инструментов, точный счёт токенов), ведёт шаг рассуждения и
просит проверки через вызовы инструментов; ход живёт в SQLite, лента транскрипта
отдаётся по SSE, интерфейс показывает урок и живой ход. Не сделано: память учителя между
ходами, зондирование, цель и план, граф знаний, отложенные повторения, импорт файлов,
сборки. Этапы и приёмка — в `roadmap.md`.

## Как запустить

Нужна модель на OpenAI-совместимом сервере с вызовами инструментов; для llama.cpp —
`llama-server -m <gguf> -c 16384 --host 127.0.0.1 --port 8080` (подробно в
`docs/local-servers.md`).

```
pnpm install
LTH_MODEL_URL=http://127.0.0.1:8080 LTH_MODEL_ID=<id или путь к gguf> \
  node packages/server/src/main.ts        # сервер на http://127.0.0.1:8765
pnpm --filter @learntogether/ui dev       # интерфейс, проксирует /api на сервер
```

Серверу, который не сообщает лимит вывода (vLLM), нужное количество токенов на ответ
даём мы: `LTH_OUTPUT_TOKENS` (по умолчанию 1024, модели с размышлением просят больше —
на Qwen3.8 выставлено 4096). Бюджет хода печатается при старте.

Без переменных модели сервер поднимается и отвечает 503 на маршрутах хода. Неверный
адрес, недоступный сервер и модель без вызова инструментов останавливают запуск с
текстом пробы. Токен доступа — `LTH_ACCESS_TOKEN`; без него сервер слушает только
петлевой интерфейс. Проверки: `pnpm verify` (lint, слои, типы, тесты).

## Как устроен

- `docs/teaching-method.md` — метод: что считаем пониманием, как проверяем, что
  делаем с заблуждениями и как строим повторения.
- `docs/architecture.md` — пакеты и направления зависимостей, доменная модель,
  поток хода, хранилище, процессы, сборка.
- `docs/tool-contracts.md` — внутренний формат ответов моделей, набор инструментов,
  правила валидации и репарации битых вызовов.
- `PROJECT_MEMORY.md` — принятые решения с причинами.
- `AGENTS.md` — правила работы в репозитории.

## Принципы, на которых не экономим

- Неизвестное о модели измеряется или спрашивается. Тихих фолбэков «безопасной
  константой» нет: неизвестный размер контекста не подменяется числом.
- Ни одного шага обучения без проверки, ни одной опоры на непроверенное.
- Ключи — в хранилище ключей операционной системы. Если его нет, ключ живёт в памяти
  процесса, а не на диске.
- Ошибки не глотаются: отказ конкретный, с тем, что можно сделать.
- Код извне (расширения) не получает прав на файлы, сеть и ключи по умолчанию.
