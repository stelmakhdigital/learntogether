# Контракт инструментов

Этап 0. Определяет: внутренний формат, набор инструментов v1, правила валидации и
репарации, состояния вызова. Реализация модельного слоя и цикла агента обязана
держать этот контракт; изменения контракта — запись в `PROJECT_MEMORY.md`.

## Внутренний формат

Один формат на все адаптеры. Адаптер обязан сделать ровно это и ничего больше.

Запрос: `role`, `blocks[]` (`text`, `thinking`, `tool_call`, `tool_result`), `tools[]`
(canonical-схема), `budget`, `reasoning_level`.

Ответ: `blocks[]` в порядке появления, `stop` (`end | tool_use | length | error`),
`usage` (вход, вход с кэша, выход, reasoning), `raw_ref` — ссылка на сохранённую wire-трассу
для диагностики.

Правила транспорта (все — из проверенного поведения серверов, см. D-024…D-029):

1. Аргументы вызова накапливаются по `tool_call.index`. Пустые дельты, «всё одним
   чанком», `finish_reason: null` на всех чанках кроме последнего — норма.
2. Вызов определяется по наличию `tool_call`, а не по `finish_reason`. Принимаем
   исторические значения `tool` и `tool_calls`.
3. `stop = length` или непарсящийся JSON при признаках обрыва — вызов мёртв.
   Обрезанный JSON не дочитываем: недопустимо угадать эталон ответа ученику.
4. `tool_choice` не ожидаем: `none` = не присылаем инструменты, `required` =
   повторяем запрос, если вызовов нет (не больше двух повторов, дальше честный отказ).
5. Reasoning-блоки: у Anthropic возвращаем побайтово, при любой правке истории
   отбрасываем весь набор thinking-блоков; у llama.cpp повторяем только если проба
   подтвердила; у остальных снимаем.
6. Параллельные вызовы в протоколе не используем, при strict-схемах
   `parallel_tool_calls: false`.
7. Vector/embedding — отдельный эндпоинт, векторы нормализуем у себя.

## Canonical-схема

Подмножество, которое принимают и облачные, и локальные серверы:

- все свойства обязательны; опциональное выражается `["T", "null"]`;
- `additionalProperties: false`;
- примитивы: `string`, `number`, `integer`, `boolean`, `array`, `object`;
- разрешены `enum`, `items`, `minItems`, `maxItems`, `minimum`, `maximum`,
  `minLength`, `maxLength`, `description`;
- запрещены `pattern`, `$defs`, `$ref`, `anyOf`, `oneOf`, `not`, `format`.

Причина: strict-режим OpenAI требует именно этой формы; vLLM без `strict` на
инструмент даёт протёкшую разметку в текст; llama.cpp не держит аргументы
грамматикой при `auto`; LM Studio вырезает корневые `$defs`. Серверам с грамматикой
можем отдать полную схему — это отдельный флаг профиля, не «попробуем и посмотрим».

## Набор инструментов v1

Завершают ход и ждут человека:

| Инструмент | Назначение | Ключевые поля |
| --- | --- | --- |
| `check_understanding` | проверка шага | `step_id`, `kind` (`single_choice`, `multi_choice`, `free_recall`, `predict`, `find_error`, `transfer`), `question`, `options[]`, `answer`, `why`, `ask_confidence` |
| `ask_learner` | открытый вопрос без эталона: замер, уточнение цели, реакция на шаг | `kind` (`probe`, `clarify_goal`, `reflection`), `question`, `expected` (`one_line`, `paragraph`, `list`) |

Фаза замера:

| Инструмент | Назначение | Ключевые поля |

| `probe_record` | результат зондирования | `items[]` = `statement`, `state` (`held`, `frontier`, `absent`), `confidence`, `basis_ref` |

Фаза плана и обучения:

| Инструмент | Назначение | Ключевые поля |
| --- | --- | --- |

| `repair_step` | ремонт непонятого шага | `step_id`, `diagnosis`, `reattach_to` |
| `session_close` | итог урока | `installed[]`, `weak[]`, `next_suggested` |

Практика:

| Инструмент | Назначение | Ключевые поля |

| Инструмент | Назначение | Права |

Инструментов «на будущее» нет. Новую область правок добавляем только с запросом.

## Правила валидации и репарации

Порог честности: ни одно исправление не меняет смысл, который увидит ученик.

Уровень 0, структура: склейка дельт, `JSON.parse`, известные ключи. Ошибка — мёртвый
вызов (см. правило 3).

Уровень 1, приведение типов (логируется в диагностику с именем сервера): строка
числа в `number`, `"true"` в `boolean`, JSON-строка вместо массива, `null` вместо
отсутствующего значения, регистр `enum`, пробелы по краям. Разрешено только когда
приведение обратимо и однозначно.

Уровень 2, семантика: `answer` ссылается на существующий вариант; `options` не
содержит дублей; у `check_understanding` есть `step_id` существующего шага в статусе
`presented`; `premises` непустой у `derivation` и пустой у `foundation`; активна
ровно одна задача практики; вопрос не обещает вариант, которого нет.

Уровень 3, повтор: результат инструмента с текстом ошибки валидатора и указанием,
какое поле исправить. Два повтора на вызов.

Отказ: после двух повторов вызов помечается `failed`, ход останавливается, экран
показывает причину дословно и что можно сделать (сменить модель, поднять бюджет,
продолжить вручную).

Не репарируется никогда: текст вопроса, формулировки вариантов, эталон ответа,
порядковые индексы вариантов, ссылки `step_id`/`claim_id`, рейтинг повторения. Это
идентичность ответов ученика; её правка искажает историю усвоения.

## Состояния вызова

Транскрипт хранит: `raw_args` (как пришло), `canonical_args`, `repairs[]`
(`level`, `field`, `from`, `to`, `server`), `state`, `error`.

Поток состояний: `started` → `args_delta` → `args_ready` → `valid` | `repairing` |
`failed` → `awaiting_learner` → `answered` | `dismissed`.

Правила: `awaiting_learner` возможен только у двух инструментов из первого списка;
в состояние `awaiting_learner` входит не больше одного вызова; ответ ученика
пишется как `tool_result` этого же вызова, с сохранением исходного порядка вариантов
и отдельно — перемешанного показа.

## Ошибки модельного слоя

Таксономия для UI и диагностики: `args_truncated`, `args_malformed`,
`schema_violation`, `semantic_rule`, `no_call_when_required`, `provider_flag_missing`
(с текстом сервера дословно), `context_overflow` (с числами: сколько нужно, сколько
доступно, откуда взялось число), `capability_unprobed` (просим измерить).

Каждая ошибка несёт: что случилось, на каком вызове, что система сделала, что
делать пользователю.

Отказ доходит до хода двумя путями и одним и тем же образом: `done` со `stop: error`
(текст в поле `error`) или исключение из транспорта — отказ подключения, не-2xx,
непарсящийся SSE-чанк. Цикл в обоих случаях отдаёт ровно одно `finished` со
`stop: "error"` и текстом источника; накопленный текст хода сохраняется (D-054).

## Что проверяется тестами

- Contract-тесты на фикстуре транспорта: дельты по чанкам, пустые дельты, весь аргумент
  одним чанком, `length` посреди аргумента, исторический `finish_reason: "tool"`.
- Replay-набор wire-трасс (по одному файлу на сервер) с эталонным внутренним ответом.
- Инвариант: после уровня 1 и 2 `answer`, `options`, индексы и `step_id` идентичны
  исходным байтам вызова.
- Инвариант цикла: у каждого шага есть проверка; ни одного `answered` без
  предшествующего `presented`.
- Инвариант репарации: любой применённый уровень записан в `repairs[]`; без записи
  изменение аргументов запрещено.
