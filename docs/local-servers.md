# Локальные серверы моделей

Справка для разработки и для живых проверок этапа 2. Флаги взяты из документации
серверов и помечены, что именно без живого запуска не подтверждено.

## Что ставим

llama.cpp `llama-server` — основной путь: OpenAI-совместимый интерфейс, локальный
запуск без демонов, готовая сборка под CUDA. Ollama — запасной путь (свой
родной `/api/embed` и `/v1/chat/completions`). Сборка под вычислительную
возможность 7.0 (Tesla V100) — отдельным запросом: там нет bf16 и FP8, только
fp16, и современные сборки движков стартуют с 7.5 и выше.

На этой машине для проверок свободна одна карта на 6 ГБ: модели 7-8B в кванте Q4
и модель эмбеддингов. Релизный таргет — 24 ГБ и выше.

## Запуск чата

```
llama-server -m <модель.gguf> --jinja -c 16384 --host 127.0.0.1 --port 8080
```

`--jinja` подставляет внешний шаблон. Проверено на b12723 с Qwen2.5-7B: без флага
вызовы тоже работают — шаблон лежит в самом GGUF (`chat_template` в `/props`).
Проверять надо наличие флага не будем, смотрим на
`chat_template_caps.supports_tool_calls`.

Полезные эндпоинты: `GET /props` (свойства инстанса), `POST /apply-template` и
`POST /tokenize` (см. ниже), `GET /v1/models` (`meta.n_ctx`, `meta.n_ctx_train`).
Верхнеуровневых `use_jinja`, `n_ctx`, `parse_tool_calls` в b12723 нет.

Точный счёт токенов без `tokenizer.json`: отрендерить промпт через
`/apply-template`, посчитать `/tokenize` по готовому промпту (шаблон сервер в
`/tokenize` сам не применяет). На пробе совпало с `usage.prompt_tokens` бит в бит —
214 против 214.

Параллельные вызовы на b12723 работают без `--parallel` (`supports_parallel_tool_calls:
true`, вернулось два вызова с `index: 0` и `index: 1`). Наш протокол их не просит,
но накопление идёт по индексу и обязана выдерживать.

Установка prebuilt-архива: `libggml-cuda.so` требует `libcudart.so.12` и
`libcublas.so.12`, они в соседнем asset'ах `cudart-...`; без них `--list-devices`
возвращает `(none)`. Карту удобнее задавать индексом (`--device CUDA4`) — по UUID
сервер отвечает `invalid device`.

## Запуск эмбеддингов

```
llama-server -m bge-m3.Q8_0.gguf --embedding --pooling cls --embd-normalize 2 \
  --host 127.0.0.1 --port 8081
```

Отдельный процесс обязателен: с `--embedding` тот же инстанс чат не обслуживает.
Векторы приводим к единичной длине на своей стороне, независимо от того, что
сервер уже нормализовал.

Проверить живьём: качество на собственном корпусе из 200 утверждений (этап 4),
скорость на батчах 8 и 64, размер ответа.

## Что делает приложение при подключении

1. Запрашивает список моделей и свойства инстанса.
2. Измеряет контекст, а не берёт его из имени модели.
3. Пробует вызов инструментов одним служебным запросом; если сервер не принял —
   показываем дословный текст сервера и недостающий флаг.
4. Пробует reasoning, зрение, эмбеддинги — по одному запросу на возможность.
5. Сохраняет пробу с временем и способом измерения; протухшую пробу перемеряет, а
   не подменяет числом по умолчанию.

Неизвестная возможность остаётся неизвестной: интерфейс спрашивает, измерить сейчас
или ввести значение вручную.

## Типовые отказы, которые мы ожидаем

| Ситуация | Что увидим | Что делает приложение |
| --- | --- | --- |
| Сервер без `--jinja` | текст вместо вызова инструмента | повтор не помогает: просим перезапустить сервер с флагом, показываем команду |
| `max_tokens` посреди аргументов | непарсящийся JSON или `finish_reason = length` | вызов отбрасывается целиком, повтор запроса |
| Сервер не отдаёт размер контекста | нет поля в свойствах | измеряем probing'ом, тихого числа по умолчанию нет |
| Модель не держит инструменты | пустой список вызовов при явно настроенных инструментах | рольteacher на такую модель не назначаем, объясняем причину |
| Нет файла токенизатора модели | нечем считать токены | просим положить `tokenizer.json`; временная верхняя оценка не запускает компакцию |
