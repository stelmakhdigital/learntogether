# Формат читаемого экспорта

Экспорт — производное от SQLite представление (D-002), а не хранилище. Нужен для
трёх вещей: переносимость на случай сбоя, чтение внешними инструментами, участие
человека в правке своих записей.

## Размещение

```
<dataDir>/
  learntogether.db            источник правды
  export/
    sessions/<sessionId>.md   один урок или практика
    graph/claims.jsonl        утверждения
    graph/chains.jsonl        цепочки
    graph/doubts.jsonl        открытые зоны сомнения
    practice/queue.md         очередь на ближайшие дни
    INDEX.md                  что где лежит и когда экспорт обновлялся
```

## Когда пишется

При закрытии сессии, по запросу из интерфейса («Обновить файлы»), перед
выключением сервера. Не на каждый ход: запись на каждый шаг добавила бы гонку с
питанием ленты и ничего бы не дала, потому что база уже содержит это содержимое.

## Детерминированность

Повторный экспорт при неизменной базе обязан дать побайтово те же файлы — иначе
нельзя ни хранить их в git, ни отличить правку человека от смены данных. Поэтому:

- порядок записей фиксирован: сессии по `created_at` затем по `id`; внутри сессии
  по `ordinal`; утверждения по `id` (не по тексту, чтобы правка текста не
  переставляла файл); цепочки по `id`;
- перевод строк LF, кодировка UTF-8 без BOM, завершающий перевод строки один;
- время в заголовках — то, что лежит в базе (UTC, ISO-8601 с `Z`), не момент
  экспорта; отметка времени экспорта живёт только в `INDEX.md`;
- пустые поля не печатаются, но пустой блок печатается как явная строка «нет»,
  чтобы отсутствие раздела не выглядело потерей;
- JSON в `.jsonl` — без переносов строк внутри записи, ключи в алфавитном порядке.

## Session markdown

```
# <формулировка цели>

- Идентификатор: <id>
- Создана: <created_at>
- Модель учителя: <endpoint/model>
- Контекст: <context_tokens> (измерено: <probed_at>)

## Шаг 3 — <формулировка>

<поданный текст шага>

> Проверка (<kind>): <вопрос>
> Ответ: <ответ ученика> — <verdict>, уверенность <confidence>
> Почему: <пояснение>
```

Мысли ученика печатаются отдельным блоком и только если пользователь не отключил
их сохранение в экспорт: содержимое личное, и по умолчанию оно в файлах есть, но
отключается одним переключателем.

Вызовы инструментов, завершившиеся ошибкой, печатаются с текстом ошибки — молча
пропущенного хода в файле быть не может.

## Graph JSONL

Одна строка на утверждение: `id`, `text`, `aliases`, `area`, `tags`,
`provenance` (сессии, шаги, источники), `doubt` (открытые), `repetition` (по
методам). Цепочки: `id`, `premises` (упорядоченные `claim_id`), `conclusion`,
`provenance`. Никаких «оценок усвоения»: их в модели нет, и в экспорт их
выдумывать незачем.

## Обратный вход

Читается человеком, редактируется им же — и обратно в базу файлы не импортируются:
источник правды один. Правка файла, которая должна повлиять на урок, сознательно
означает «импортировать как заметку»: отдельная операция с явным подтверждением,
иначе правка истории усвоения произошла бы незаметно для системы.

## Read-only CLI

`apps/cli` открывает базу флагом `readonly` и не имеет кода записи — не как
соглашение, а как единственный доступный режим соединения. Команды: показать
сессию, показать узел с провенансом, очередь, учёт токенов за период, поиск.
Тест, доказывающий read-only: попытка записи через то же соединение обязана
падать.

## Чего в экспорте нет

Ключи доступа, настройки сервера, векторы эмбеддингов, сырые wire-трассы
диагностики. Перечисленное лежит отдельно и в `export/` не попадает.
